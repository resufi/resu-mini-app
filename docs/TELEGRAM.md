# Telegram Mini App

Как этот проект живёт внутри Telegram и что нужно настроить, чтобы он там работал.

## Что уже сделано в коде

**Скрипт Telegram.** В `index.html` подключён `telegram.org/js/telegram-web-app.js`.
Его нельзя положить в бандл: Telegram отдаёт свою версию под клиент, и подменять
её нечем. Скрипт грузится синхронно до приложения, иначе `window.Telegram.WebApp`
не существует в момент первого рендера.

**Инициализация.** `src/hooks/useTelegram.ts` на старте вызывает `ready()` и
`expand()`, запрещает свайп-закрытие (`disableVerticalSwipes`, Bot API 7.7) и
красит шапку, фон и нижнюю панель в наш `--bg`. Без этого у человека с тёмной
темой Telegram вокруг светлой страницы остаётся чёрная рамка.

**Размеры.** Telegram не даёт странице настоящих `100vh`: клавиатура и шапка
меняют высоту на лету. Хук пишет в корень `--tg-viewport`, `--tg-viewport-stable`
и четыре `--tg-safe-*`, обновляя их по событиям `viewportChanged`,
`safeAreaChanged` и `contentSafeAreaChanged`. Заставка тянется на
`--tg-viewport`, отступы страницы прибавляют safe-area. В браузере переменные
имеют запасные значения (`100dvh`, нули), поэтому код одинаков везде.

**Возврат из кошелька.** `VITE_TWA_RETURN_URL` уходит в
`actionsConfiguration.twaReturnUrl` у TonConnect. Без него человек после
подтверждения транзакции остаётся в кошельке и не понимает, сработало ли.

**Хаптика.** Отклик на переключении сети и на исходе транзакции — успех и
отказ различаются на ощупь.

**Solana скрыта внутри Telegram.** В вебвью Telegram нет расширений кошельков,
а диплинки уводят из мини-аппа без обратной дороги. `visibleChains()` в
`src/lib/chains.ts` убирает вкладку; в обычном браузере она на месте.

## Что настроить снаружи

1. **Бот и мини-апп в @BotFather**
   - `/newbot` — если бота ещё нет;
   - `/newapp` — выбрать бота, задать имя, короткое имя (оно станет частью
     адреса), картинку и **URL опубликованного приложения**;
   - адрес мини-аппа получится вида `https://t.me/<bot>/<app>`.

2. **Переменные сборки**
   - `VITE_TWA_RETURN_URL=https://t.me/<bot>/<app>`
   - `VITE_SITE_URL` — публичный адрес сборки, если он нужен в ссылках.

   Локально — в `.env`, в CI — в секретах репозитория (см. `.github/workflows/pages.yml`).

3. **Манифест TonConnect** должен лежать по публичному https и содержать тот же
   `url`, что и адрес приложения. Сейчас он вынесен в отдельный репозиторий и
   задаётся `VITE_TONCONNECT_MANIFEST_URL`; проверяется `npm run check-manifest`.

## Посмотреть телеграмный вид локально

Без бота и туннеля: `?tg=1` подсовывает приложению поддельный
`window.Telegram.WebApp`, и включается вся телеграмная ветка кода — safe-area,
высота вьюпорта от Telegram, скрытая вкладка Solana, хаптика в консоли.

```
npm run dev
```

- `http://localhost:5173/?tg=1` или `?tg=ios` — отступы как на iPhone: 47px
  сверху под чёлку, 34px снизу под полосу жестов, плюс 46px шапки Telegram;
- `?tg=android` — 24px сверху, снизу ничего;
- `?tg=desktop` — нулевые отступы;
- без параметра — обычная браузерная версия.

Мок живёт в `src/lib/telegramMock.ts` и обёрнут в `import.meta.env.DEV`,
поэтому в продакшен-сборку не попадает: проверяется тем, что строки
`tg mock` нет в `dist`.

Чего мок не покажет: настоящих жестов закрытия, поведения клавиатуры
телефона, вибрации и возврата из кошелька. Это только внешний вид и раскладка
— для остального нужен туннель.

## Локальный туннель

Telegram открывает мини-апп со своего устройства, поэтому `localhost` ему не
виден — нужен публичный https:

```
npx cloudflared tunnel --url http://localhost:5173
```

Vite 6 проверяет заголовок `Host` и по умолчанию пускает только `localhost`,
отвечая «Blocked request. This host is not allowed». Домены популярных
туннелей разрешены в `vite.config.ts` (`server.allowedHosts`); для другого
сервиса добавь его домен туда же.

Если порт 5173 занят другим проектом, Vite молча возьмёт 5174 — и туннель
надо направлять на тот порт, который он напечатал, иначе снаружи окажется
чужое приложение.

## Проверка

`npm run dev` открывается и в браузере — Telegram-часть выключается сама, когда
`platform === "unknown"`.

Внутри Telegram проверить стоит: раскрытие на весь экран, отсутствие закрытия
свайпом вниз, цвет шапки, поведение при открытой клавиатуре в поле суммы,
возврат из кошелька после подписи и отсутствие вкладки Solana.

## Чего здесь нет

`initData` не проверяется: проверять подпись должен сервер по секрету бота, а
бэкенда у проекта нет. Пока приложение ничего не знает о личности пользователя
и ничего ему не персонализирует, этого и не требуется — но как только появится
сервер, подпись `initData` обязательна к проверке на нём.
